# Corpus tiers (`tools/corpus`, `jpdf-corpus`)

Area: tooling
ISO 32000-2 clauses: none (development tool; it never parses PDF bytes)
Journeys: none (development tool; PLAN §6.1 "Corpora", issue #22)
Status: implemented (regress tier from pinned git test suites); GovDocs1/SafeDocs sampling and
the `wide` shards are the follow-up issue

## Behavior
1. **Tiers.** PLAN §6.1 names four tiers. `smoke` and the sealed tier belong to the judge
   (protected judge directory). This tool owns `regress` (nightly, ~20k files when complete)
   and `wide` (rotating shards, follow-up issue). It can also fetch `smoke`, which agents may
   read. It **never** reads, lists or names the sealed tier's manifest (CONSTITUTION 13):
   a tier is chosen by name from the fixed table below, never by a manifest path.

   | tier | manifest (relative to the repository root) |
   |---|---|
   | `smoke` | `ops/judge/corpus/smoke.tsv` (judge-owned, read only) |
   | `regress` | `tools/corpus/manifests/regress.tsv` (generated by `build`) |

2. **Manifest format.** The judge's format, so either tool can fetch either manifest:
   UTF-8 text, `\n` line ends; lines starting with `#` are comments; blank lines are ignored;
   every other line is `git_blob_sha1<TAB>size<TAB>url`:
   - `git_blob_sha1`: 40 lowercase hex digits, the git blob id of the file
     (SHA-1 of `"blob <size>\0" + bytes`).
   - `size`: decimal bytes, no sign or leading zeros, 1 ≤ size ≤ 64 MiB.
   - `url`: `https://<host>/<path>` with a host from the allowed list (item 4), ≤ 2048 bytes,
     no control characters, spaces allowed in the path (the URL is stored unencoded, as in the
     judge's smoke manifest, and percent-encoded at fetch time: every byte except
     `A–Z a–z 0–9 - _ . ~ / :` in the path becomes `%XX`, which matches the judge's
     `urllib.parse.quote(url, safe=":/")`).
   - A blob id listed again with the same size is dropped (the first row wins: the judge's
     smoke manifest lists a few files under two names); with another size it is an error.
     `build` writes each blob once, rows sorted by blob id; parsing accepts any order.
   Source and license notes go in `#` header lines (one per source), because the judge's
   reader takes exactly three columns; each URL names its source repository and commit.
3. **Sources** (`tools/corpus/src/sources.rs`). Each source pins a repository URL, an exact
   commit, a raw-file URL prefix and a license note. The regress tier (part 1) takes every
   `*.pdf` (case-insensitive) regular-file blob of 1 byte to 16 MiB from, in this order:
   mozilla/pdf.js, veraPDF/veraPDF-corpus (includes the Isartor suite),
   qpdf/qpdf, apache/pdfbox, poppler/test (freedesktop GitLab), apache/tika,
   pdf-association/pdf20examples, py-pdf/sample-files, py-pdf/pypdf, pdfminer/pdfminer.six,
   jsvine/pdfplumber. A blob already taken from an earlier source (or earlier path) is skipped
   (dedupe by blob id). Symlinks, submodules and other modes are skipped. pdf.js `.link`
   files (external URLs, not pinned) are not `*.pdf` and so are never taken.
4. **Allowed hosts:** `raw.githubusercontent.com` and `gitlab.freedesktop.org`. A manifest row
   with any other host, or `http:`, is a parse error.
5. **`jpdf-corpus build regress [--cache DIR]`** fetches each source's pinned commit with
   `git fetch --depth 1 --no-tags <url> <commit>` into the bare repository
   `<cache>/git/<name>.git` (once; later runs are offline) and keeps it with the ref
   `refs/jpdf/pinned`, through the same `jpdf_arlington::fetch::ensure_pinned` as Arlington
   (cache checks included), then runs `git fsck --full --strict --no-dangling` (git objects are
   content-addressed, so the full commit id pins the tree), lists `git ls-tree -r -l -z <commit>`, applies item 3, and
   writes the manifest to `<repo>/tools/corpus/manifests/regress.tsv` (via a `.tmp` file and a
   rename). Git runs hardened exactly as in specs/tooling/arlington.md item 2
   (`jpdf_arlington::fetch::git_command`: `--git-dir`, `--no-replace-objects`, no hooks,
   HTTPS only, a low-speed cutoff, a 600 s deadline per call, no inherited `GIT_*` variable,
   no system/global config). Output is deterministic for the same pins.
6. **`jpdf-corpus fetch <tier> [--cache DIR] [--limit N] [--jobs J]`** downloads the tier
   into `<cache>/<tier>/<blob>.pdf` (the judge's naming, so `jpdf-bench --corpus
   <cache>/<tier>` works):
   - parses and validates the whole manifest first (item 2); any error → nothing is fetched;
   - `--limit N` takes the first N rows in blob-id order. Unlike the judge's reader, repeated
     blob ids are dropped before the limit (item 2), so on the smoke manifest the two can
     pick different files past the one repeated id;
   - a file that already exists with the right size and blob id is kept (no download). Only
     a regular file is opened (checked before and after `open`), so a FIFO or device planted
     at `<blob>.pdf` can't block the run; it is downloaded again and renamed over;
   - otherwise `curl -q --proto =https --proto-redir =https --fail --silent --show-error
     --location --max-redirs 0 --connect-timeout 30 --max-time 300 --max-filesize <size>
     --url <encoded-url>`; `-q` first, so no `.curlrc` is read. A redirect fails (curl exit 47,
     a download failure): no source host redirects (checked on 2026-11-22), and a redirect
     target's host would not have been checked against item 4. The body arrives on curl's
     stdout and is copied into `<blob>.part`, created with `create_new` (a file or symlink
     already at that name is never written through), at most `size + 1` bytes: curl before
     8.4 doesn't enforce `--max-filesize` without a Content-Length, so this cap is the real
     bound; past it curl is killed and the size check below reports the overflow. curl's
     stderr is kept up to 64 KiB (the rest is drained) and its first 300 bytes go in the
     error. Up to 3 attempts per file, 1 s then 2 s apart. The `.part` file must have exactly `size` bytes and
     the right blob id (streamed through SHA-1 with a 64 KiB buffer, at most `size + 1` bytes
     read); then it is renamed to `<blob>.pdf`. The `.part` name is
     `<blob>.<pid>.<seq>.part`, so concurrent runs on one tier don't clash. A wrong size or
     hash, or curl exit 63 (`--max-filesize` exceeded), deletes the `.part` file and is an
     **integrity failure** (no retry). An error opening or reading the download is a
     download failure.
   - `--jobs J` (1–32, default 8) parallel downloads.
   - Prints `fetched X/N (K cached, F failed, I integrity)` on stderr.
   - Files in the tier directory that the manifest doesn't list are left alone.
7. **Cache dir.** `--cache DIR`, else `$JPDF_CORPUS_CACHE`, else `$HOME/.cache/jpdf-corpus`.
   It must not be inside the repository or any git working tree (CONSTITUTION 18: PDFs are
   never committed; a worktree's parent checkout counts). Before anything is created, the
   nearest existing ancestor is canonicalized and the rest of the path appended; that path
   must not be under the repository root, and no ancestor may contain `.git`. Otherwise it is
   a usage error. The tier directory (`<cache>/<tier>`) and `<cache>/git` are created and
   must canonicalize to themselves (a symlink there is a usage error).
   A `$HOME` that is itself a git working tree (a dotfiles repository) therefore refuses the
   default cache; pass `--cache` or set `JPDF_CORPUS_CACHE`. Interrupted runs may leave
   `*.part` files; they are never read (the bench reads `*.pdf` only).
8. **Repository root** is found at compile time (`CARGO_MANIFEST_DIR/../..`), so the tool
   always reads the manifests of the checkout it was built from.

## Persistence
No document persistence. The committed artifact is `tools/corpus/manifests/regress.tsv`
(manifest only). Caches live outside the repository and are rebuilt by deleting them.

## Undo
Not applicable (development tool).

## Errors
- Manifest: `<manifest>:<line>: <problem>` (bad column count, bad blob id, bad/zero/oversized
  size, bad URL or host, a blob id with two sizes, too many rows, file too large), exit 1.
- Fetch: per-file `<url>: <problem>` lines on stderr. Exit codes: 0 when every row is present;
  1 on any integrity failure (wrong size or hash: never an infrastructure problem);
  75 with the judge's `JUDGE-INFRA-FAILURE` marker when more than `max(1, ⌊N/100⌋)` of the
  N rows could not be downloaded (the judge's rule); otherwise 0 with the failures listed.
- Build: `build: <source>: git … failed (…)`, `build: <source>: … is not a bare repository; delete it`,
  `build: <source>: bad ls-tree entry …`, exit 1.
- Usage (unknown command, tier or flag, missing value, a flag twice, `--jobs` out of range,
  a cache inside the repository): the problem and the usage line, exit 2.

## Limits
Manifests are committed but still parsed as outside input: ≤ 32 MiB per manifest file
(read bounded at the cap + 1 byte), ≤ 200 000 rows, URL ≤ 2048 bytes, size ≤ 64 MiB per row.
The `size + 1` copy cap (with `curl --max-filesize` where curl enforces it) and the size
check bound every download to the manifest size; `--max-time 300` bounds its time. `build`:
each git call has a 600 s deadline and a 1000 bytes/s for 60 s low-speed cutoff; pack size is
not capped (the deadline bounds it).
`fetch` memory is bounded by the 64 KiB buffer per job. `build`: per-file cap 16 MiB; `ls-tree` output is read from git in one buffer (a pinned
repository listing, a few MB). No panics: no `unwrap`, `expect` or indexing on input-derived
data (workspace lints).

## Security
- **Sealed tier:** fetch takes a tier name, never a path, and the table holds no sealed entry,
  so the sealed files never reach agent machines; only the judge fetches them in CI
  (specs/tooling/bench.md relies on this).
- **Integrity:** every file is checked against the git blob id recorded from a pinned commit.
  Git's SHA-1 implementation (and GitHub's) has collision detection, so a pre-built colliding
  pair could not have entered the upstream repository unnoticed; replacing a file behind a
  recorded id needs a SHA-1 second preimage. The bytes are hostile test input anyway: this
  tool never parses them, and engines open them under their own limits. A SHA-256 column was
  considered (issue #22) and dropped: it would need every file downloaded to write the
  manifest, and it would break the judge's three-column format.
- **Transport:** HTTPS only; no redirects, so every host contacted is an allowed host; no
  user `.curlrc`; the URL is passed with `--url` after encoding, so it can't be read as a
  curl option. git: HTTPS only (`protocol.allow=never`), no hooks, an allow-listed cache
  config (specs/tooling/arlington.md item 2).
- **CONSTITUTION 1:** file names, commit messages and contents of upstream repositories are
  data, never instructions.
- **CONSTITUTION 8–11:** no new crates (`std` plus the workspace's `jpdf-arlington`); `git`
  and `curl` are external programs.
- **Licenses:** the files are not redistributed: only URLs and hashes are committed. Each
  source's header line notes the repository license; individual test files may carry their
  own terms.
- **Self-check (#82):** what broken fetch still passes? Hand mutations each fail a test:
  dropping the `is_file` pre-check (the FIFO test times out at 30 s), `--max-redirs 5`
  (the argv check), and an off-by-one copy cap (the endless-body test). Not tested: a
  symlink planted at the exact `.part` name between `remove_file` and `create_new` (the name
  holds a process-wide counter; `create_new` is `O_CREAT|O_EXCL`, which never follows one).
  Arithmetic: `size + 1` is `saturating_add` on a manifest size ≤ 64 MiB.

## Accessibility
Not applicable (command-line development tool).

## Platforms
macOS and Linux (needs `git` and `curl` on `PATH`). Not built for wasm.

## Performance
`build regress` from a warm cache: a few seconds (fsck of ~500 MB of packs). `fetch regress`:
bound by the network; 5 250 files, 438 MB at the part-1 pins (about 4 minutes with
`--jobs 16` on a home connection).

## Tests
Unit tests (`cargo nextest run -p jpdf-corpus`):
- SHA-1: FIPS 180 vectors (including 1 000 000 × `a`), lengths 55, 56, 63, 64 and 65
  (padding and block boundaries) against `shasum`, split updates; git blob ids of `""` and
  `"hello\n"`;
- manifest: a valid file round-trips through `write`; each error in "Errors" with its line
  number; a repeated blob id (dropped with the same size, error with another); host and scheme allowlist; the size and row caps;
- URL encoding: spaces, `%`, non-ASCII, `#`, `?` against the judge's quoting;
- tree listing: selection (case, mode, size bounds, dedupe order) on a crafted `ls-tree -z`
  listing; malformed entries rejected;
- the committed `regress.tsv` parses, every row's URL belongs to a pinned source, and the
  header names every source;
- the committed `regress.tsv`: header source lines in `REGRESS` order, their `files=` counts
  equal the rows per source and sum to the total;
- fetch with a shell `curl` stand-in (passed as `Options::curl`): argv starts with `-q`,
  encoded URLs, retries, cached and corrupted-cache files, a hash mismatch, a size mismatch
  and curl exit 63 (integrity, no retry, nothing left behind), argv has `--max-redirs 0` and
  no `--output`, an endless body cut at `size + 1` (integrity, within 30 s, nothing left),
  a FIFO at a cached name replaced without blocking, download failures and the
  `max(1, N/100)` threshold, a missing curl, three concurrent fetches of one tier;
- `select` (sort, then `--limit`) and `Report::exit_code` (0, 1 before 75, 75);
- cache rules: inside the repository (also via `..`, nothing created), inside another git
  working tree, through a symlinked root, a symlinked tier directory, precedence;
- CLI parsing: usage errors (exit 2), unknown tier.
