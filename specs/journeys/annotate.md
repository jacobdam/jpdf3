# Journeys: annotate and comment

Area `ANN`. PLAN §4 (Annotate), feature groups F-AN-1 … F-AN-5 in [specs/TRACE.md](../TRACE.md).
Inventory and coverage: [RESEARCH.md](RESEARCH.md). Format: ops/judge/CONTRACT.md §4.
The M5 gate (PLAN §8) requires every journey here to pass.

Shared rules for every journey in this file (the reader rules at the top of
[reader.md](reader.md) also apply: fixtures, web network policy, file-handle adapter,
engine-owned logic, browser-safe shortcuts, engine gate, fixed seeds):

- **Engine owns annotations.** Creating, hit-testing, moving, resizing, erasing, appearance
  generation, flattening and XFDF/FDF parsing and writing all happen in the Rust engine; the
  native layer sends pointer and keyboard events in page coordinates and displays the
  engine's results (CONSTITUTION 6). Every value from the native layer (coordinates, colors,
  sizes, text, image bytes) is validated by the engine and rejected with a typed error when
  out of range (CONSTITUTION 5).
- **Strict writing (CONSTITUTION 17).** Every annotation we create or change is written per
  ISO 32000-2 §12.5: correct `/Subtype`, `/Rect` that contains the appearance, an `/AP /N`
  appearance stream generated by the engine, `/F` with the Print flag set, a unique `/NM`, `/M`
  modification date, `/T` author (the author name preference; default the OS user name on
  macOS, "Guest" on web), and `/P` pointing to its page. Colors are DeviceRGB.
- **Persistence check.** "Save and verify" means: save (macOS Cmd+S; web Ctrl+S or the toolbar
  Save button, written through the file-handle adapter; with the no-handles flag, the download
  fallback is captured by Playwright's `download` event) → the save is incremental: the
  original file's bytes are an exact prefix of the saved file (PLAN M5 minimal incremental
  save) → close the document → reopen the saved file → the annotation is present with the
  same type, `/Rect` within 0.5 pt, colors, opacity, width and text → `jpdf-cli` and the
  reference tools see the same annotation count on that page → the MuPDF and Poppler renders
  of that page at 72 dpi each differ from the unannotated original inside the annotation's
  `/Rect` and match our render there within the render-ratchet tolerance → `qpdf --check`
  (run as an external program) reports no errors.
- **Undo** is Cmd+Z / Ctrl+Z, **redo** Cmd+Shift+Z / Ctrl+Shift+Z (web also Ctrl+Y), plus Edit
  menu items on macOS and toolbar buttons on web. J-ANN-20 covers undo for every operation.
- **Pointer input in tests:** web drives `pointerdown/move/up` through Playwright's mouse API
  at page coordinates converted by the app's test hook; macOS uses XCUITest coordinate drags.
  Drawn strokes use fixed point lists from the test, never random input.
- **Hostile text:** every journey that types or imports text includes the string
  `<b>x</b><img src=x onerror=alert(1)>` once; it is stored and shown literally, never
  interpreted as markup, and no image request or alert happens.

## J-ANN-01: Highlight selected text
- milestone: M5
- platform: web, macos
- test: e2e.web.ann_highlight_persists, e2e.macos.ann_highlight_persists

Steps: open a 3-page text fixture → choose the Highlight tool → drag across one line on page 1
→ a Highlight annotation appears whose `/QuadPoints` cover exactly the selected glyphs (one
quad per line, from the engine's text layout) → the default color is yellow at the tool's
default opacity → select existing text first with the Select tool, then click Highlight in the
selection's context menu → a second highlight covers that selection → change the tool color
to green and highlight a third phrase → it is green → save and verify (three Highlight
annotations, colors yellow, yellow, green; `/CA` as set) → the highlighted text is still
selectable and copyable after reopening (J-RD-16).
Error branch: drag the Highlight tool over an image-only area with no text → nothing is
created and a hint says that no text was found.

## J-ANN-22: Export and import comments as XFDF and FDF
- milestone: M5
- platform: web, macos
- test: e2e.web.ann_xfdf_fdf, e2e.macos.ann_xfdf_fdf

Steps: open a fixture with 8 annotations including a thread with replies → Export comments
→ XFDF → the file is well-formed XML with one element per annotation and the replies'
`inreplyto` links → Export → FDF → the file parses with the engine and has the same 8
annotations → open the original file without annotations → Import the XFDF → all 8 appear
on the right pages with the same properties and threads → undo → Import the FDF → the same
→ save and verify.
Error branches (each shows a message and changes nothing): XFDF with a DOCTYPE or external

depth limit, a file larger than the import size limit, annotations for a page that doesn't
exist (skipped and counted in the message), malformed colors or coordinates, and an FDF
whose `/F` names another file (never opened).
