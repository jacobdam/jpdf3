# Journeys: annotate and comment

Area `ANN`. PLAN §4 (Annotate), feature groups F-AN-1 … F-AN-5 in [specs/TRACE.md](../TRACE.md).
Inventory and coverage: [RESEARCH.md](RESEARCH.md). Format: ops/judge/CONTRACT.md §4.
The M5 gate (PLAN §8) requires every M5 journey here to pass; J-ANN-26 needs the M6 writer.

Shared rules for every journey in this file (the reader rules at the top of
[reader.md](reader.md) also apply: fixtures, web network policy, file-handle adapter,
engine-owned logic, browser-safe shortcuts, engine gate, fixed seeds):

- **Engine owns annotations.** Creating, hit-testing, moving, resizing, erasing, appearance
  generation, flattening, permission checks and XFDF/FDF parsing and writing all happen in the
  Rust engine; the native layer sends pointer and keyboard events in page coordinates and
  displays the engine's results (CONSTITUTION 6). Every value from the native layer
  (coordinates, colors, sizes, text, image bytes, stored stamps and signatures read back from
  app storage) is validated by the engine and rejected with a typed error when out of range
  (CONSTITUTION 5). Where a journey says a UI control is disabled, the test also calls the
  binding directly and expects the engine's typed error.
- **Strict writing (CONSTITUTION 17).** Every annotation we create or change is written per
  ISO 32000-2 §12.5: correct `/Subtype`, a `/Rect` that contains the appearance, an `/AP /N`
  appearance stream generated by the engine, a unique `/NM`, `/M` modification date, `/T`
  author and `/P` pointing to its page. Colors are DeviceRGB. Flags `/F` (§12.5.3) by kind:
  - visible annotations (markup, shapes, ink, stamps, text boxes): Print;
  - sticky notes (Text): Print, NoZoom, NoRotate;
  - replies: Print, NoZoom, NoRotate, drawn with no icon of their own (shown in the thread);
  - review statuses (J-ANN-18): Hidden;
  - Popup: no flags (never printed).
- **Author name.** `/T` is the author name preference. It defaults to "Guest" on both
  platforms (never the OS login name); the first time the user annotates, a non-blocking banner
  offers to set it.
- **Counting.** "N annotations" counts annotations other than Popup and Link annotations.
  Counts outside our app are read with `qpdf --json` and `mutool show <file> <page>/Annots`;
  Poppler is used for renders only.
- **Persistence check.** "Save and verify" means: save (macOS Cmd+S; web Ctrl+S or the toolbar
  Save button, written through the file-handle adapter; with the no-handles flag, the download
  fallback is captured by Playwright's `download` event) → the save is incremental: the
  original file's bytes are an exact prefix of the saved file (PLAN M5 minimal incremental
  save), and the update section redefines no object number that the journey didn't change →
  close the document → reopen the saved file → each annotation is present with the same
  type, `/Rect` within 0.5 pt, colors, opacity, width and text → our count and the counts from
  `qpdf --json` and `mutool` agree on each page → for each visible annotation (not Popup,
  Hidden, or reply), the MuPDF and Poppler renders of its page at 72 dpi each differ from the
  unannotated original inside its `/Rect` and match our render there within the
  render-ratchet tolerance → `qpdf --check` (an external program) reports no errors.
- **Undo** is Cmd+Z / Ctrl+Z, **redo** Cmd+Shift+Z / Ctrl+Shift+Z (web also Ctrl+Y), plus Edit
  menu items on macOS and toolbar buttons on web. While a text field is focused, these act on
  the field's text; otherwise on the document. J-ANN-20 covers undo for every operation.
- **Pointer input in tests:** web drives `pointerdown/move/up` through Playwright's mouse API
  at page coordinates converted by an app test hook; macOS uses XCUITest coordinate drags.
  Like the engine gate, the coordinate hook exists only in test builds. Drawn strokes use fixed
  point lists from the test, never random input. Nothing depends on wall-clock timing; dates
  come from a fixed test clock.
- **Hostile text:** every journey that types or imports text includes the string
  `<b>x</b><img src=x onerror=alert(1)>` once; it is stored and shown literally, never
  interpreted as markup, and no image request or alert happens.
- **Hostile images:** every image picker (stamps, signatures) and every imported image is
  decoded by the engine (never the platform decoder) under its image limits. The shared error
  set: a non-PNG/JPEG file; a truncated PNG; dimensions past the limit (decompression-bomb
  header); a small image with huge compressed ancillary chunks (zTXt, iCCP); a file over the
  byte-size limit. Each is rejected with a message and nothing is placed. Supported variants
  (16-bit and interlaced PNG, CMYK and progressive JPEG) are accepted and render correctly.

## J-ANN-01: Highlight selected text
- milestone: M5
- platform: web, macos
- test: e2e.web.ann_highlight_persists, e2e.macos.ann_highlight_persists

Steps: open a 3-page text fixture → choose the Highlight tool → drag across one line on page 1
→ a Highlight annotation appears whose `/QuadPoints` cover exactly the selected glyphs (one
quad per line, from the engine's text layout) → the default color is yellow at the tool's
default opacity → select a second phrase with the Select tool, then choose Highlight in the
selection's context menu → a second highlight covers that selection → change the tool color
to green and highlight a third phrase → save and verify (three Highlight annotations: yellow,
yellow, green; `/CA` as set) → the highlighted text is still selectable and copyable after
reopening (J-RD-16).
Error branch: drag the Highlight tool over an image-only area with no text → nothing is
created and a hint says that no text was found.

## J-ANN-22: Export and import comments as XFDF and FDF
- milestone: M5
- platform: web, macos
- test: e2e.web.ann_xfdf_fdf, e2e.macos.ann_xfdf_fdf

Steps: open fixture A with 8 annotations including a thread with replies → Export comments
→ XFDF → the file is well-formed XML with one element per counted annotation and the
replies' `inreplyto` links → Export → FDF → the file parses with the engine (under the PDF
parser's Limits) and has the same 8 annotations → open fixture B (the same pages, no
annotations) → Import the XFDF → all 8 appear on the right pages with the same properties
and threads → undo → Import the FDF → the same → save and verify.
Error branches (each shows a message and changes nothing, unless it says "skipped"):
- XFDF with a DOCTYPE or external entity: rejected, never resolved or fetched;
- elements nested past the engine's depth limit; a file over the import size limit; more
  annotations than the per-import limit;
- annotations for a page that doesn't exist: skipped and counted in the message;
- malformed colors or coordinates;
- an FDF `/F` or an XFDF `<f href>` naming another file: never opened;
- FDF `/JavaScript`, field `/A` or `/AA` actions, and XFDF links with URI or Launch actions:
  never run or imported (CONSTITUTION 7); the rest of the file imports and the message counts
  what was dropped;
- `<contents-richtext>` or `/RC` with a DOCTYPE, `<script>`, `<img>` or deep nesting: the
  DOCTYPE is rejected; otherwise the text is imported as plain text, nothing is fetched;
- imported appearance streams and base64 image data: held to the same stream and image
  limits as J-ANN-14 (the shared hostile-image set).
