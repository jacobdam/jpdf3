## Main findings
1. **The automation's own trust boundary is weaker than the engine's (#161, #162, both sev:high, owner-todo).** The
   Codex launcher sandbox restricts writes and network, not reads (the sealed corpus manifest, ~/.codex and ~/.ssh
   are one read away), and its pre-sandbox `cargo fetch` and cleanup trust the reviewed branch. The guard's tag check
   can be skipped by quoting `gh`, and the guard fails open on unexpected exceptions. All of these files are
   protected, so the next sessions write proposals (rule d) and the owner applies them.
2. **The license check is still bypassable (#163).** `image-set()` outside .css files (inline `<style>`, `style=`
   attributes, a `?x.css` query import) shipped a fake MPL package's file to `dist/` with `licenses: ok`. #99 (Rollup's
   module graph) remains the durable fix.
3. **The memory model assumes freed memory is reused (#165).** On macOS, libmalloc keeps freed large buffers: 19
   page kids with 2^20-entry dictionaries peaked at 1.24 GB against about 0.6 GB modelled. The judge (glibc) is not
   affected as far as macOS shows.
4. **The ADR 0009 gates aren't mechanical (AC.2, AS.56).** `gates.toml` has no security criterion, so `gate m4`
   passes with a `sev:high` issue open, and the rubric has no row for policy-gate bypasses. Both are protected or owner
   decisions: ops/proposals/security-gates-in-gate-tool.md.
5. **Test strength.** Four limits still lack an at-limit test (AC.4–AC.6, AC.8 → #87); JBIG2 has no salvage check
   and CCITT no aligned 2-D fixture (#166).
6. **Docs drift**, fixed in this PR: specs/cli/jpdf-cli.md still said the page-tree walk keeps one object alive
   (stale since the #107 resolve cache, AC.7); AUTOMATION didn't mention the Codex reviewer or the CONSTITUTION 1.2
   exception (AC.9); three applied proposals still read as pending (AC.10). ops/TICK.md:204 still cites the guard
   proposal as pending; TICK changes only in retros, so that goes to retro 0002.
