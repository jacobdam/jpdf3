## Method
Four fresh reviewer subagents ran in parallel, each given only its area and CONSTITUTION.md:
- security review of the engine and apps
- security review of the tooling
- code review of `jpdf-traits` (the traits and their conformance suites)
- code review of everything else

Alongside them:
- one completeness agent compared PDFgear's 952 UI strings with RESEARCH.md, the journeys and PLAN §4
- `cargo mutants` ran on the parser crates
- I did the housekeeping myself

The reviewers proved their claims with crafted PDFs (release `jpdf-cli`, `/usr/bin/time -l`) and with broken toy
adapters in a scratch copy of `jpdf-traits` under `target/`. The repo tree was not modified.

The hostile-input core held up. No input made the code panic, no unchecked arithmetic on input was found, and there is no `unsafe`
anywhere. Depth, object and lexing budgets apply on every path, including look-ahead. Overlap rejection is sound. A 491 MB
worst-case file opened in 2.1 s at 995 MB RSS. The macOS app and helper are sandboxed with hardened runtime, and the web
CSP is strict (Trusted Types, no `unsafe-inline`). There is no PDF logic in Swift or TS.

## Main findings
1. **Conformance suites accept broken adapters (#80, #81, #68).** Each case below was proven by a toy that passes today:
   - A byte cap of 0 treated as "unlimited" bypasses the per-document budget.
   - Flate distances above 2 KiB are never decoded.
   - X.923 padding passes the AES checks.
   - An RC4 keystream that restarts every 16 bytes passes.
   - Junk "hostile fonts" satisfy the hostile coverage requirement.
   - Image tolerance 255 accepts an all-zero decoder.

   These matter most, because every future adapter (#16) is admitted on these suites.
2. **E2E harnesses can report `pass` for a failed run (#76).** The web reporter ignores the run status. On macOS the release
   sandbox check runs after `e2e.json` is written. The judge grades journeys from that file.
3. **Memory margins (#77, #79).**
   - The CLI reads 512 MiB of an oversized file before rejecting it, and it hangs on a FIFO.
   - Number tokens and a cloned `/Prev` allocate outside every budget.
   - The trait contracts don't bound decoder working memory or CPU.
   - The per-document decoded budget (4 GiB) is twice the judge's address-space cap, and nothing bounds caches.
4. **Lenient-read gaps (#78).** Each of these is rejected, though consensus engines open them:
   - an incremental update whose trailer omits `/Root`
   - a page leaf without `/Type`
   - an xref offset past EOF (unless it exceeds u32)
5. **Tooling availability (#82, #83).**
   - git fetches have no deadline, so a stalled fetch on a PR blocks CI for up to 6 h.
   - The `GIT_*` scrub is a denylist.
   - Bench engine process groups outlive the bench when it is interrupted.
6. **Flaky test (#75).** `timeout_kills_the_whole_process_group` failed once under parallel load.
7. **`cargo xtask nightly` exits 0 doing nothing** (comment on #19).

## Test strength (cargo mutants 27.1.0)
`cargo mutants -p jpdf-syntax -p jpdf-engine -p jpdf-cos`, tests from those crates plus `jpdf-cli`:

| Run | Mutants | Caught | Missed | Timeout | Unviable |
|---|---|---|---|---|---|
| Each crate's own tests only | 257 | 137 | 98 | 1 | 21 |
| Plus cross-crate tests | 257 | 189 | 44 | 3 | 21 |

That is 81% of viable mutants caught. The main gap: **no limit has an exact-boundary test** (every `>` survives as `>=`). Also missed: the
generation check in `resolve`, the overlap boundaries, lowercase hex digits, and `as_integer`. → #87.
